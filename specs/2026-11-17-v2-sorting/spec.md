# 2026-11-17 v2：分拣中转站（ToB 主场景）

> 本文件只写规格：要什么、怎么算做到。plan 与 tasks 在 spec 确认后另开，不在本文件里。
> 结构对齐 `specs/000-template/spec.md`（用户故事 → 成功标准 → 待澄清 → 不做），v2 另把目标 / 边界 / 约束与依赖显式拆开。
> 上位依据：`docs/PRD.md#v2：分拣中转站（ToB 主场景）`、`docs/decisions/0006-ai作为分拣站.md`。

## 用户故事

- 作为**一线销售**，我把一段通话纪要粘进去，想让系统告诉我这算哪家客户、补了哪个要素、这家该不该优先、下一步给什么价值，以便我不用自己整理和排序。
- 作为**一线销售**，我看到分级和我预期不同时，想直接改掉并写一句原因，以便下次系统更接近我的判断。
- 作为**销售负责人**，我想每周看到推进、卡点与分级变动，以便决定资源往哪投、谁的客户该收回。

## 目标

1. 人只做**投料、确认、改判**三件事；一次投料的交互成本 ≤「看一眼 + 一次点击」。
2. AI 承担四类判断（归属 / 要素 / 分级 / 出库），**每个判断都带理由与原文片段**，没有依据的判断不许落库。
3. 五个入口（分拣台 / 客户 / 客户详情 / 复盘 / 设置）串成一条链：投料 → 分拣 → 货架 → 出库；功能之间由分拣单连接，不再是一堆并列页面。
4. 分级可解释、可改判、可追溯：AI 建议值 / 人工最终值 / 差异原因三列可查，历史只追加。
5. 归属判断必须**可解释、可审计**：每次归属都留下"哪一级判定（精确键 / 字符串 / 向量 / 灰区模型复核）+ 分数 + 阈值 + 候选列表"的审计记录；**向量相似度不得单独作为合并依据**（见 `docs/decisions/0007-归属用确定性漏斗.md`）。

## 边界

**做什么**

1. 投料口：粘贴文本、上传文本文件；归属到已有客户或新建客户。
2. 分拣站：一次投料产出一张分拣单（四个判断 + 四个操作）。
3. 货架：客户按 A/B/C 分组；每家一张信息卡（ToB 四要素）+ 时间线。
4. 出库口：今日待办（排序 + 建议动作 + 价值点）、话术草稿（复用 v1）、周复盘（汇总 + 3 个校准问题）。
5. 分级：默认权重策略、两种生效模式、变更留痕、偏好样本收集。
6. 保留 v1 的教培模板作为第二模板，仅用于引擎可迁移性验证。
7. **归属走三级确定性漏斗**：① 规范化（繁→简、全角→半角、去「有限公司 / 股份 / 集团」等后缀、去括号、别名表）→ ② L0 精确键（手机号 / 邮箱 / 统一社会信用代码 / 规范化全称，命中即归属）→ ③ L1 字符串相似（rapidfuzz `token_sort_ratio` + Jaro-Winkler，0–100）→ ④ L2 向量相似（沿用现有百炼 `text-embedding-v3` 算 cos）。上一级定案就不再走下一级；LLM 只在灰区（候选 ≤3）复核，不裸猜。
8. **阈值校准脚本**：用 50 对人工标注的客户对子扫 precision / recall 曲线，产出建议阈值并可写回模板；阈值不写死在代码里。
9. **出处对齐校验**：模型给出的 `source_span` 必须能在原文里定位（先精确子串，再用 rapidfuzz 模糊对齐拿偏移）；定位不到的字段按"无依据"丢弃并留诊断。

**不做什么**

1. 不做 ToC 专用界面（教培模板不做专属页面）。
2. 不做权限 / 多租户 / 登录。
3. 不做微信 / 邮件抓取，也不做自动发送。
4. 不做"这单会成 / 会丢"的成交概率预测（分级只是资源投放优先级）。
5. 不做可视化流程编辑器。
6. 不做移动端。
7. 不做 Excel 深度解析（首版只保证"能投进去并被识别为表格文本"，见「已决决策 7」）。
8. 不在本规格内改动 v1 的流程块契约、必填规则与回收逻辑。

## 可测验收标准

1. **归属 + 要素**：**Given** 库里已有客户"华远建设"，**When** 投一段提到该公司与"走公开招标"的对话，**Then** 分拣单归属到"华远建设"，补上"决策流程与预算 · 采购方式"且带原文片段，且不新建重复客户。
   - 验证：调用分拣接口 / 在分拣台观察；查 `sorting_batches` 新增一行的 `lead_id` 与 `source_span` 非空。
2. **要素缺失可指导**：**Given** 某客户缺"决策流程与预算"，**When** 打开客户详情，**Then** 显示缺项清单与"下次该问什么"（具体问题句），不只是"未填"。
   - 验证：客户详情页观察 + 接口返回 `missing[]` 每项含 `question` 字段。
3. **分级带理由**：**Given** 一条预算、时间点、决策人齐全的投料，**When** 出分拣单，**Then** 分级为 A/B/C 之一，附理由与 ≥1 条依据片段；无依据片段时该分级不落库。
   - 验证：分拣单展开依据；`pytest -q` 中"无依据不落库"用例通过。
4. **改判留痕三列**：**Given** 一张 AI 判为 B 的分拣单，**When** 人工改为 A 并填原因，**Then** `grading_history` 新增一行，含 AI 建议值 B、人工最终值 A、差异原因非空、操作人与时间。
   - 验证：查 `grading_history`；客户详情分级历史可见三列。
5. **待办无空建议**：**Given** 库里有 A/B/C 客户与到期跟进，**When** 打开今日待办，**Then** 每条都有"建议动作 + 给什么价值"；构造一条无价值点的候选，**Then** 它不出现。
   - 验证：待办接口返回中每条 `value` 字段非空；用例覆盖"无价值点被过滤"。
6. **无价值跟进可识别**：**Given** 一次跟进记录的"本次提供的价值"为空，**When** 保存并查看复盘，**Then** 该次被标记为"无价值跟进"并计入复盘统计。
   - 验证：跟进详情标记可见；复盘接口 `no_value_count ≥ 1`。
7. **复盘可交付**：**Given** 本周有分级变动与卡点，**When** 打开复盘页，**Then** 列出本周推进 / 卡点 / 分级变动，并展示 3 个校准问题可作答，答案写入 `preference_samples`。
   - 验证：复盘页观察；`preference_samples` 新增行。
8. **模式切换**：**Given** 设置为「AI 直接定 + 留痕」，**When** 投料，**Then** 分级直接生效但 `grading_history` 有记录；切回「AI 提议 + 人确认」后，**Then** 新分拣单需点同意才入库。
   - 验证：设置页切换 + 两次投料对比；两次都可在历史中追溯。
9. **不回归**：**Given** v2 改动落地，**When** 跑 `pytest -q`，**Then** v1 的 247 条仍全绿；`tests/test_no_industry_words.py` 通过（分拣规则里不出现行业词）。
   - 验证：`.venv\Scripts\python.exe -m pytest -q`。
10. **精确键命中不调模型**：**Given** 库里客户"华远建设"登记手机号 138xxxx0001，**When** 投一段含同一手机号的纪要，**Then** 分拣单直接归属该客户，审计记 `scorer='exact'`、`score=100`，且**该次归属未调用 LLM**（judge 调用计数为 0）。
    - 验证：`pytest -q tests\test_matching_funnel.py -k exact`；fake judge 记录归属复核调用次数；`sorting_batches` 的 `match_audit` 里 `scorer=exact`。
11. **灰区不自动归属**：**Given** 原文只给出公司名"华远"，库里唯一相近候选"华远建设"的 L1 分数为 90（85–95 区间）且**无第二字段佐证**（地区 / 行业 / 联系人都对不上），**When** 出分拣单，**Then** 该单进人工队列（`band='review'`），`lead_id` 为空，不落任何事实。
    - 验证：`pytest -q -k fuzzy_band`；`sorting_batches` 新增行 `lead_id IS NULL`、`match_audit.band='review'`。
12. **伪造出处片段必须被丢弃**：**Given** 模型返回的要素片段是"客户说预算两百万"，而原文只有"预算大概在一百多万"（原文里不存在该句），**When** 落分拣单，**Then** 该字段被丢弃（不落 `facts`、不出现在要素块），并记一条 `span_misaligned` 诊断（丢弃片段 / 最佳模糊分数 / 原文长度）。
    - 验证：`pytest -q tests\test_span_align.py -k misaligned`——该用例对着"只校验片段非空"的旧实现会失败，可复现地证明漏洞已堵。

## 约束与依赖

- **分层**：`domain/`（sorting / card / grading）只放纯规则，不读库、不调模型、不碰时钟；`services/`（sorting / card / grading / todo / review）不 import `adapters/`；装配只在 `entrypoints/bootstrap.py`。由 `lint-imports` 锁死。
- **依赖 v1 能力**：`raw_item`（投料原文）、`fact`（已生效事实与锁定）、`followup`（跟进三要素，v2 增加"本次提供的价值"）、`templates/*.yaml`（权重与阈值取值）、`adapters/llm`（四类判断的调用与 fake 实现）。
- **模型**：DeepSeek；所有 `pytest` 注入 fake LLM，真实调用只出现在显式脚本里。每次判断记录模型名 / prompt 版本 / 输入输出 hash（沿用 v1 留痕规则）。**DeepSeek 官方 Chat Completions 不支持 `json_schema` 严格模式（会 400）**，只支持 `json_object`：约束靠"schema 文本 + 落库前校验 + 有限重试"，不靠严格模式。
- **新增依赖 `rapidfuzz`**（MIT 协议，纯 Python 包 + C++ 内核）：L1 字符串相似（`token_sort_ratio` / `Jaro-Winkler`）与出处片段的模糊对齐都用它；装包走镜像 `-i https://mirrors.aliyun.com/pypi/simple/`，版本写进 `requirements-dev.txt`。向量继续用现有百炼 `text-embedding-v3`，不新增 embedding 供应商。
- **数据**：SQLite 新增 `sorting_batches`、`grading_history`、`preference_samples` 三张表，均只追加；前端不缓存业务状态。
- **前端**：Vue3 + Vite，只调后端 API；五入口（分拣台 / 客户 / 客户详情 / 复盘 / 设置）；必填 / 阈值 / 分级规则不在前端复制一份当权威。
- **合规**：话术仍受禁用词约束（保过 / 保证提分 / 退费承诺不落库）。
- **时间**：v2 按增量交付，每个增量一条可验收命令；本规格不承诺交付日期。

## 已决决策

> 原「未决问题」第 1–6 条已于 2026-11-17 定稿，保留原编号；结论直接约束 plan / tasks，实施阶段不再重议。

1. **要素字段与现有 `facts` 如何映射** —— 结论：**复用 `fact`**，在 `facts` 表加 `card_section` 列标记"属于四要素哪一块"（基础信息 / 需求痛点 / 决策流程与预算 / 跟进记录），不新建 `card_field` 表。理由：一份事实只能有一个真源，v1 已有的"来源 + 原文片段 + 人工锁定"规则正是信息卡要的，另起表必然双写并重造一遍锁定逻辑。
   - **不改 v1 锁定语义**：`card_section` 只是归类标签，不参与"谁覆盖谁"的判定；存量行的该列允许为空，读取时按 `field` 映射兜底，迁移只加列、不做一次性回填。
2. **归属不确定时怎么办** —— 结论：进**待认领池**，置信度阈值 **0.7**；**多候选**（无唯一胜出）或最高分 **低于 0.7** 一律进池，**不自动新建客户**。理由：错归属比多一次点击贵得多（客户资产被污染后无法自动修复），且 PRD 已定"AI 只提议归属，不自动改归属"。
   - **2026-11-18 修订**：单一 0.7 阈值被**三级漏斗**取代（见上「目标 5」「边界·做什么 7–9」与 `docs/decisions/0007-归属用确定性漏斗.md`）；阈值改由标注样本校准后写进模板，0.7 只作为"分数无任何依据"时的兜底口径保留。
3. **分级权重默认值放哪** —— 结论：**放模板**，`templates/` 下 ToB / ToC 各一套权重，与块组合、阈值同源。理由：换模板就该换分级口径，权重跟着行业走；放全局配置会让"换模板"变成只换一半。
4. **今日待办排序公式** —— 结论：**A/B/C 降序 → 超时程度（已过期 > 今天 > 本周）→ 缺项多者优先**；**每家最多一条**；同分取**最久未联系**者。理由：先按"该投多少资源"分档，再用时效兜住"再不打就凉"的那批，最后用缺项把"信息不全、打过去也白打"的提前；一家一条防止待办被一家客户刷屏。
5. **复盘页是否导出** —— 结论：**v2 不导出**，只做页面观察。理由：导出会牵出模板与字段口径问题，先把内部闭环做实，导出列入 v3 候选。
6. **两种分级模式的粒度** —— 结论：**全局一刀切**（设置页一个开关，作用于整个团队）。理由：v2 团队 4–10 人，按人 / 按客户覆盖会让设置页与留痕字段复杂度翻倍，收益不成比例。

**补充默认（不属于原 1–6 编号，同样已定）**

7. **Excel 只当文本表格** —— 结论：投料口接受表格文件时只按纯文本读入与留存，不做单元格结构化解析；要结构化就人工粘成文本。理由：v2 的瓶颈是分拣判断，不是表格解析。
8. **旧文档矛盾句回改** —— 结论：PRD 与架构里"AI 只在提炼与话术 / 唯一入口 / 只有两处"一类表述，直接改成现在的真实状态（四类判断 + 话术生成），不留"v2 增补 / 被扩展"这类补丁措辞。理由：文档里留补丁，后来者分不清哪句是现行规则。
