# 演示脚本（5 分钟）

> 用法：演示前照着念，不即兴发挥。每步都写清了「点什么 / 屏幕上会出现什么 / 这句对应哪个卖点」。

## 准备（开场前 2 分钟，观众不用看）

```powershell
# 1) 干净数据 + 演示数据（已有数据的库会跳过，不翻倍）
Remove-Item -Force data\app.sqlite3 -ErrorAction SilentlyContinue
.venv\Scripts\python.exe scripts\seed_demo.py            # → SEED_OK leads=4 followups=2 facts=1

# 2) 建一次假向量索引：第 5 步「生成话术」要靠它给出资料引用
.venv\Scripts\python.exe scripts\build_index.py --fake    # → INDEX_OK chunks=22 model=fake

# 3) 起后端（假模型，不联网、不花钱）
$env:PYTHONPATH='src'; .venv\Scripts\python.exe -m uvicorn salescopilot.entrypoints.api.app:app --port 8000

# 4) 另开终端起前端
cd web; npm run dev                                       # → http://localhost:5173
```

打开页面，先确认左右两件事：顶部徽标是「模式：假模型」（要主动说明：**假模型的文字是占位，不能当真实结论**）；仪表盘数字是 4 / 1 / 4 / 2。

## 场景设定

一个 4 人小团队：老板 1 人，课程顾问 3 人（李娜、王强、赵敏），做**成人职教**（考证 / 技能提升）课程，学员是上班族，成交靠课程顾问一条一条跟。

演示数据正好 4 条线索，每条代表一种状态：

| 线索 | 归属 | 阶段 | 时间 | 提醒 |
|---|---|---|---|---|
| 张校长 | 李娜 | 线索入库 | 2 小时前创建 | **红**（超过 30 分钟未首联） |
| 王主任 | 公海（无人） | 首次联系 | 3 天前创建 | **灰**（没有下次跟进时间） |
| 李老师 | 王强 | 需求确认 | 约定时间已过 2 天 | **黄**（反馈窗口超时） |
| 陈校长 | 王强 | 成交/关闭 | 6 天前创建 | 无（已结束，不再占视野） |

## 第 1 步：仪表盘（约 40 秒）

- **点什么**：什么都不点，先看页面最上面的「仪表盘」卡片。
- **屏幕上会出现**：线索总数 4 · 公海 1 · 本周新增 4 · 本周跟进 2 · 24h 首联率 100.0% · 无下次跟进占比 0.0%；下面一行 **红 1 黄 1 灰 1**、久未新增跟进 0 条。
- **对应卖点**：**过程可见**。老板不用问"最近怎么样"，一屏就知道有几条客户在公海里漂着、几个顾问的跟进正在超时。

## 第 2 步：公海认领 → 释放（约 50 秒）

- **点什么**：滚到页面底部「公海（1 条未分配）」→ 点王主任那行「认领」→ 弹窗填「赵敏」；然后用页面顶部的「公海 0 条」筛选按钮看一眼，再回到列表里点王主任那行的「释放」。
- **屏幕上会出现**：认领后王主任的「归属」列从"未分配"变成"赵敏"，公海面板变空、仪表盘公海变 0；释放后又回到"未分配"、公海回到 1 条。
- **对应卖点**：**客户是公司的资产**。线索能收回到公海、能被别人重新认领——客户不属于某个销售的通讯录。

## 第 3 步：粘贴客户原话 → 提炼（约 60 秒）

- **点什么**：找到张校长那行（风险列显示"红"）→ 点「记录跟进」展开 → 展开「原文提炼与事实」→ 在文本框粘贴一段话：
  > 张校长说价格有点贵，还在考虑，下周再约时间详细聊聊课程安排。
  
  先点「保存原文」，再点「提炼」。
- **屏幕上会出现**：提示「本次采纳 4 条」；事实表多出 4 行：
  **异议 = 价格（原文片段「贵」）· 核心需求 = 待确认决策（「考虑」）· 约定时间 = 下周（「下周」）· 决策人 = 校长（「校长」）**，
  来源都是 `AI·fake`、置信度 80%。
- **对应卖点**：**AI 在底层、可追溯**。AI 不写结论，只把原话拆成字段；每个字段都钉在原文的某几个字上，点一下就知道它是从哪句话来的。

## 第 4 步：人工改一个事实 → 再提炼不覆盖（约 50 秒）

- **点什么**：在事实表里点「异议」那一行的值（现在是"价格"）→ 下拉改成"效果"→ 保存；再粘贴第二段原话（里面再提一次"价格"），保存原文并点「提炼」。
- **屏幕上的变化**：异议的来源从 `AI·fake` 变成 **人工**，旁边多一个「已锁定」徽标；第二次提炼显示「本次采纳 0 条」，跳过的 3 条原因分别是「人工锁定，跳过」×1 与「重复值」×2；事实表里「异议」仍然是"效果"。
- **对应卖点**：**人工优先、不漂移**。人改过的字段就是最终值，模型不会拿新的一段话把它悄悄改回去。

## 第 5 步：生成话术草稿 → 确认落库（约 60 秒）

- **点什么**：同一个展开区里点「生成话术草稿」→ 看正文和引用列表 → 在下面选「异议」、填下次跟进时间（比如后天）→ 点「确认落库」。
- **屏幕上会出现**：一段草稿正文，右上带 `AI·fake` 徽标；正文下面列着 `[1] 来源：service_policy.md　片段：试听后 3 天内会有顾问回访…`；点「确认落库」后，跟进列表里多出一条记录（结论就是草稿正文）。
- **对应卖点**：**AI 产出被流程约束**。没有资料依据就不许生成、没有引用就不许落库、没人点确认就不会变成跟进记录——AI 只是"写草稿的实习生"。

## 第 6 步：推进阶段被必填拦住（约 40 秒）

- **点什么**：在王主任那行点「推进到 需求确认」。
- **屏幕上会出现**：顶部错误条：「进入阶段「需求确认」前必须先填写「决策人」；进入阶段「需求确认」前必须先填写「核心需求」」，王主任的阶段**没有变**。
- **对应卖点**：**流程不是摆设**。阶段不是想跳就跳；缺什么、缺几项，系统当场说清，而不是事后靠人回忆。

## 收尾一句话（10 秒）

"这套东西里，AI 只在两个地方出现——提炼客户原话、写话术草稿；怎么推进、谁能看、什么时候提醒，全是可测试的流程规则。"

## 如果被追问（照这三句答）

**1. 和一个普通 CRM 有什么区别？**
普通 CRM 是"填表存档"，流程是厂商写死的，改流程要提需求；我们是**流程引擎**：6 个流程块 + 三份行业模板，行业差异只在 `templates/*.yaml`，引擎层由测试保证不含行业词（`pytest tests/test_no_industry_words.py`）。另外我们的 AI 有明确边界：只在提炼与话术两处，且产出必须过流程规则才能落库。

**2. 提炼准确率多少？**
不宣称一个准确率数字。我们有一份可复跑的基线：`python scripts/run_eval.py --suite extract --live`，20 条**合成**样本上字段 precision 0.6552 / recall 0.8261 / 原文片段有效率 1.0（报告在 `data/reports/extract-20261114-224019.json`）。样本是合成的，不代表真实客户分布，所以产品用两条机制兜底：每条事实必须带原文片段（可回查），人一改就锁定（AI 不许覆盖）。

**3. 为什么不让 AI 直接发消息给客户？**
两个原因：一是合规——这个行业里承诺效果、保过一类说法是硬红线，草稿命中禁用词会被直接拦下，机器发出去就没有这道人工闸门；二是责任——发错一句话的代价远高于销售点一次"确认"。所以 AI 到"草稿"为止，落库动作永远由人发起。
