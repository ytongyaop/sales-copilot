# 演示脚本（ToB 版，6 分钟）

> 用法：演示前照着念，不即兴发挥。每步都写清了「点什么 / 屏幕上会出现什么 / 这句对应哪个卖点」。
> 主线是**一个团队的一天**：先看今天该跟谁 → 投一段料变成分拣单 → 客户货架上分档看清 → 详情里看四维与缺项 → 生成话术并确认落库 → 周复盘校准。
> 数字是 2026-11-18 在干净库上跑出来的样例，**以现场实际输出为准**；带「（示例）」的地方是假模型写的占位文字，不要念成结论。

## 场景设定

一个 4 人小团队卖**企业软件与设备集成**：老板 1 人（周会上看数字），销售 3 人（李娜、王强、赵敏）。
单笔 3 万–120 万，决策链 2–4 人，交付周期 4–12 周；客户来自转介绍、行业展会和主动触达。
他们最痛的不是「记不住联系人」，而是**报价发出去就没下文**：过程看不见，人也带不走。

演示库里 5 条客户，一条代表一种状态：

| 客户 | 归属 | 阶段 | 关键事实 | 提醒 |
|---|---|---|---|---|
| 华远建设集团 | 李娜 | 方案会 | 120 万，决策链与预算都清楚，信息卡 14/14 | **黄**（约定 3 天前已过） |
| 明远软件科技 | 李娜 | 需求确认 | 8 万，缺「决策流程」「预算区间」，约定就是今天 | **黄**（反馈窗口超时） |
| 宏图建材 | 王强 | 首次联系 | 3 万，5 天没动静，上次没约定下次 | **灰**（没有下次跟进时间） |
| 恒信智能 | 李娜 | 需求确认 | 四维里只缺「成交金额」→ 判不出档 | 无 |
| 王主任 | 公海（无归属） | 线索入库 | 什么都没有，5 小时没联系 | **红**（超过 120 分钟未首联） |

## 准备（开场前 60 秒，观众不用看）

```powershell
# 1) 干净数据 + ToB 演示数据（已有数据的库会跳过，不会翻倍）
Remove-Item -Force data\app.sqlite3 -ErrorAction SilentlyContinue
.venv\Scripts\python.exe scripts\seed_demo.py
#    → SEED_OK leads=5 followups=3 facts=41 grades=3

# 2) 只给 ToB 资料建索引（假向量、离线；第 5 步「生成话术」要靠它给引用）
.venv\Scripts\python.exe scripts\build_index.py --fake --docs-dir data\knowledge\tob
#    → INDEX_OK chunks=24 model=fake

# 3) 起后端（假模型，不联网、不花钱）
$env:PYTHONPATH='src'; .venv\Scripts\python.exe -m uvicorn salescopilot.entrypoints.api.app:app --port 8000

# 4) 另开一个终端起前端
cd web; npm run dev
#    → http://localhost:5173
```

**60 秒检查清单**（逐条打勾再开讲）：

1. 顶部徽标是「模式：假模型（演示数据不可信）」——开场就要主动说明「假模型的文字是占位，不能当真实结论」；
2. 「设置」页「模板（4 份）」里能看到「ToB 企业销售 tob_enterprise」——换场成功；
3. 「分拣台」的「今日待办」是 **5 家**，不是空的；
4. 「客户」页仪表盘是 5 / 1 / 4 / 3（客户总数 / 公海 / 本周新增 / 本周跟进）；
5. 索引建过（没建的话第 5 步点「生成话术」会被后端拒：「未引用资料」）。
6. **8000 / 5173 没有残留旧进程**（旧进程跑的是老代码，页面行为会对不上这份脚本）：
   `Get-NetTCPConnection -LocalPort 8000,5173 -State Listen -ErrorAction SilentlyContinue` 没有输出才开讲；
   有输出就先按 PID 收掉（`Stop-Process -Id <PID>`）再重起后端与前端。

> 提醒颜色按**跑脚本那一刻**的时间差算：若在 UTC 04:00（北京时间 12:00）之前跑，
> 明远那条「反馈窗口」黄灯不会出现，红 / 黄 / 灰就变成 **1 / 1 / 1**，其余不受影响。

## 第 1 步：分拣台 → 今天先打给谁（约 50 秒）

- **点什么**：什么都不用点，打开就是「分拣台」页签，看最上面那张卡「今日待办（5 家）」。
- **屏幕上会出现**：五行，按 A → B → C → 未分级排好（最后两条是「没分级」与「待补全」并成一档），每行三行字：
  - 华远建设集团 `A`　**A 类 · 约定 3 天前已过 · 要素齐全** → 「今天：按上次约定回电」「给什么：上次承诺的跟进」；
  - 明远软件科技 `B`　**B 类 · 约定今天 · 缺「影响者」「决策流程」** → 「今天：补问「影响者」」「给什么：方案与报价区间说明」；
  - 宏图建材 `C`　**C 类 · 还没约定下次时间 · 缺「痛点强度」「我方匹配点」** → 「给什么：同类客户案例」；
  - 王主任 `未分级`　**未分级 · 还没约定下次时间 · 缺「公司全称」「所属行业」** → 「给什么：公司背景资料」；
  - 恒信智能 `未分级`　**未分级 · 还没约定下次时间 · 缺「影响者」「预算区间」**（待办把「待补全」与「没分级」并成一档显示；货架与详情页上它是 `待补全`）。
- **对应卖点**：**过程可见，且不给空建议**。排序是「分级 → 到期 → 缺项数 → 最久没联系」四层，代码里写死的是顺序、不是数字；
  每家只说一句「今天做什么、给他什么」，**「给什么」取不到就整条不出现**——宁可少一条，也不给一句空话。

## 第 2 步：投料 → 分拣单（四块判断 + 出处）→ 接受（约 70 秒）

- **点什么**：往下滚到「投料」框，粘贴这段通话纪要：
  > 华远建设集团今天下午开了方案会，项目经理和采购总监都在。他们最关心的是材料台账和施工进度能不能打通。预算在 120 万左右，约定下周去现场看进度看板。

  右上「归属到已有客户」下拉**选「华远建设集团」**，点「投进去」。
  （不选也能投，但那样只会给出归属候选、单子进「待认领池」等你去认领——演示时不用绕这一步；
  系统只对「精确键命中」自动归属，只是名字像的都要人确认，这是 ADR-0007 的灰区口径。）
- **屏幕上会出现**：上方弹出分拣单，状态「待复核」，**置信度 100.0**，下面四块：
  - **归属**：命中客户 华远建设集团；
  - **要素**：4 条，每条都带原文片段——`基础信息 · 公司全称：华远建设集团`「华远建设集团」、
    `需求与痛点 · 核心需求：预算在 120 万左右`「预算在 120 万左右」、`决策流程与预算 · 决策者：经理`「项目经理和采购总监都在」、
    `跟进记录 · 约定时间：2026-11-25`「约定下周去现场看进度看板」；
  - **分级**：`待补全`　「缺「成交金额」，总分区间 0.50–0.80 跨档（0.45 / 0.75），需补全「成交金额」」+ 三条依据引号；
  - **下一步**：动作 + 提供的价值。
- **点「接受」**：提示「**已写入 0 条事实，跳过 4 条（人工锁定，跳过）**」。
- **对应卖点**：**AI 只在四处分拣判断里出现，而且每条都钉在原文上**——出处的片段能在原话里找到，找不到的会被丢掉（有「丢弃诊断」可展开）。
  另外两点要主动说明：
  1. 分拣单上的「分级」只按**这一段原文**算，所以原文没提金额时它说「待补全」——那是提醒你「这条料还缺什么」，不是给客户改档；
  2. 接受时 4 条全部被跳过，是因为华远这几项**都是人一条条确认过的**：人改过的字段就是最终值，模型不许拿一句新话把它盖掉。
  写不写库也永远由人点，AI 到此为止。

## 第 3 步：客户货架 → 分档、覆盖度、风险（约 40 秒）

- **点什么**：点页签「客户」。
- **屏幕上会出现**：
  - 「仪表盘」：客户总数 5 · 公海 1 · 本周新增 4 · 本周跟进 3 · 24h 首联率 100.0% · 无下次跟进占比 20.0%；
    下面一行 **红 1　黄 2　灰 1**，久未新增跟进 2 条；
  - 「客户货架（5 家）」四个分组：**A 类 1 / B 类 1 / C 类 1 / 待分级 2**（空组也保留标题）；
  - 每张小卡：右上角一个**风险色点**（悬停显示后端给的原话，例如「约定时间已过 3 天未更新」）、档位徽标、归属人、
    覆盖条 `覆盖 100%（14/14）· 缺 0 项`、`下次约定 2026-11-15`；华远那条覆盖 100%，宏图只有 36%（5/14）。
- **对应卖点**：**客户是公司的资产 + 一眼看出谁在漂**。档位不是销售自己贴的标签，是规则按四维算出来的；
  覆盖度和缺项数与详情页是**同一个函数**算的，两处数字永远一致。右下「公海 1」筛选一点，就能看到没人认领的那条。

## 第 4 步：客户详情 → 四维分解 + 缺项问题句 + 改判留痕（约 80 秒）

- **点什么**：点「明远软件科技」那张小卡。
- **屏幕上会出现**：
  - 顶部：名称 + `B` 徽标 + 李娜 + 阶段「需求确认」，信息卡覆盖 50%（7/14），旁边「推进到 方案会」「补字段」两个按钮；
  - 「分级」卡：**四维分解**——成交金额 `已知 0.4` 权重 30% / 紧迫度 `已知 1.0` 权重 30% / 决策清晰度 `已知 0.5` 权重 20% / 需求匹配度 `已知 1.0` 权重 20%；
    分数区间 `0.72 – 0.72`；理由「四维齐全（金额 0.4 / 紧迫 1.0 / 决策 0.5 / 匹配 1.0），加权 0.72 落在 0.45–0.75 之间 → B」；
  - 「历史（最新在前）」两行：`B → B`（人工定档，理由「缺决策流程与预算区间，先按 B 级跟」）与 `B → （未定档）`（规则提议那一行）；
  - 「信息卡」：分区 `基础信息 3/3`、`需求与痛点 3/3`、`决策流程与预算 1/5`、`跟进记录 0/3`，未填的字段下面直接跟着一句
    **「问：他们内部走什么流程？招标还是议价？」**——问题句来自模板，不是前端写死的。
- **点什么（续）**：在「改判」里选 `A`，理由填「客户口头确认二期预算，决策人已见过，按 A 级跟」→ 点「确认改判」。
- **屏幕上会出现**：历史最上面多一行 `B → A`（理由 + 操作者），客户徽标变成 `A`。
- **对应卖点**：**规则算分、人拍板、两边都留痕**。规则只认已落库的事实；事实没变时点「重新评估」还是 B——
  改判是人的判断，所以必须写理由（少于 2 个字后端直接拒），并且**只追加、不覆盖**，事后能回答「谁在什么时候把 B 改成了 A、为什么」。

## 第 5 步：生成话术 → 引用 → 确认落库（约 70 秒）

- **点什么**：同一页滚到「话术草稿」→ 点「生成话术草稿」。
- **屏幕上会出现**：一段正文 + `AI·fake` 徽标，正文下面列着引用：
  `[1] 来源：tob_pricing_policy.md　片段：需要与客户既有系统对接时，每增加一个接口按 1.5–3 万元计……`（示例）。
  接着在下面选异议「价格」、填下次跟进日期、填一句「本次提供的价值」（比如「二期预算的口径说明 + 接口报价单」）→ 点「确认落库」。
- **屏幕上会出现（续）**：「跟进时间线」多一条记录，下面带 **「本次提供的价值：……」**——这条价值就是第 6 步复盘里的「无价值跟进」对照项。
- **对应卖点**：**AI 产出被流程约束，且一次录入多处复用**。没有资料依据不许生成、没有引用不许落库、没人点确认就不会变成跟进记录；
  确认一次，跟进留痕与「本次提供的价值」同时到位——这也是复盘能算「空转了几次」的前提。
  （凭据都在这条草稿上：模型名 `AI·fake`、引用清单、以及后端记录的耗时与 token。）

## 第 6 步：复盘 → 本周数字 + 卡点 + 3 个校准问题（约 60 秒）

- **点什么**：点页签「复盘」。
- **屏幕上会出现**：
  - 标题「本周（11-11 11:13 → 11-18 11:13）· 本周还没答校准问题」；
  - 六个数字：新增客户 4 · 推进次数 8 · 关闭客户 0 · 卡住的客户 4 · 待补全档位 1 · 无价值跟进 1；
  - 「卡点」：红（王主任 超过 120 分钟未首联）· 黄 ×2（华远 / 明远）· 灰（宏图 没有下次跟进时间）；
  - 「缺项前三」：决策流程与预算 4 家缺 · 跟进记录 4 家缺 · 需求与痛点 2 家缺；
  - 「本周改档」：**明远软件科技 B → A**，理由就是你刚在第 4 步填的那句；
  - 「无价值跟进」：宏图建材 · 老板说先看看，等这批货出了再说……
- **点什么（续）**：在最下面「本周校准问题」里回答**至少一条**（例如「这周你把哪家从 B 提到了 A？为什么？」→「明远：二期预算口头确认了」），
  点「提交作答」→ 提示「已保存 1 条作答」，页面切成「本周已作答」回放。
- **对应卖点**：**每周校准一次，样本进库**。三个问题问的是「人怎么判的」，不是「系统算出了什么」；答案写进偏好样本，下周的复盘与调阈值都从这来。
  同一周再提交一次后端会回 **409「本周已作答，下周再校准」**——样本只追加不改写，一周只留一种说法（前端答过之后会收起表单，409 是兜底）。

## 如果被追问

**1. 和一个普通 CRM 有什么区别？**
普通 CRM 是「填表存档」，流程是厂商写死的；我们是**流程引擎**：6 个流程块 + 4 份行业模板，行业差异只在 `templates/*.yaml`，
引擎层由测试保证不含行业词（`pytest tests\test_no_industry_words.py`）。同样的代码，把 ToB 模板换成教培 / 软件外包 / 建材都能跑——
删掉「方案会」这个块时，引用了它的模板当场校验失败，没引用的照样通过，这是「积木真复用」的机器证明。

**2. 分级怎么定？**
四维加权：成交金额 30% / 紧迫度 30% / 决策清晰度 20% / 需求匹配度 20%，权重与门槛都写在模板 `grading:` 段，代码里没有数字。
上限 0.75 才进 A，且**四维必须齐全**；0.45 到 0.75 之间是 B；算出来跨档（比如缺成交金额）就是「待补全」，不硬判。
**模型不参与打分**，它只负责把打分要用的那几项事实从原话里抽出来（ADR-0008）。

**3. 阈值怎么来？**
分两类。提醒阈值（首响 120 分钟 / 反馈窗口 4 小时 / 3 天没动静）来自模板，是行业经验值，改一行 YAML 就生效；
归属漏斗的两个阈值（97 / 86）是**扫出来的**：`scripts/calibrate_thresholds.py` 在 50 对人工标注的客户对子上扫 precision / recall，
报告落在 `data/reports/matching_calibration.md`，阈值也写回模板 `matching:` 段，能回查「这个数字是怎么来的」。

**4. AI 会不会编？**
两道闸门加一道人工锁。第一，每条要素必须能在原文里定位到片段，定位不到直接丢，并在分拣单的「丢弃诊断」里报出来；
第二，话术必须引用资料，引用为空就拒绝生成（真模型会重试一次，还空就 422）；
第三，人改过的字段锁定，后续提炼不许覆盖。另外每次调用都记模型名、提示词版本、输入输出哈希、耗时与 token，能回放。

**5. 为什么不自动发消息给客户？**
两个原因。一是合规：报价与承诺只能以书面协议为准，草稿命中「保过 / 最低价 / 百分百」一类禁用词会被直接拦下，机器发出去就没有这道闸门；
二是责任：发错一句话的代价远高于销售点一次「确认」。所以 AI 到「草稿」为止，落库动作永远由人发起。
