# Pitch

## Problem
中小企业的销售流程各不相同：买标准 CRM，装不进自己的流程；找人定制，一次几万还改不动；最后回到 Excel + 微信 + 口头规则 —— 线索靠人记、过程看不见、换个销售就断档，什么时候该跟进、为什么丢单，全靠回忆。

> 公司层的痛更深：客户被销售捏在自己手里 —— 人一走客户就没了，公司没有客户资产，过程无法度量也无法交接。

> 示例场景（成人职教课程顾问）：24 小时内没首联的线索默默凉掉；试听完当天下不了反馈，家长的决策记忆三天就衰减；台账只写"已联系"，管理者看不到卡在哪。

## Appetite
一周 7×8 ≈ 50 小时，交付可演示 v1（FastAPI 后端 + Vue 前端 + 一条教培主流程）。超时砍功能不延期，砍单顺序：仪表盘 → 对照模板 → CSV 导入。有效预算按 42 小时规划，留 8 小时缓冲；第 4 天中午为强制砍单检查点——主链未通即砍仪表盘、对照模板、CSV 导入。

## Solution
一套销售流程引擎 + 6 个可组合流程块 + 行业模板。

- 引擎（唯一代码，不含任何行业词）：状态机 · 必填校验 · 阈值提醒 · 归属与回收 · 全留痕 · AI 步骤接口
- 6 个块：intake / first_contact / qualify / appointment / proposal / close
- 模板：教培（主演示，含试听）· 软件外包（含方案会）· 建材（跳过邀约）
- AI 只做两件事：生成跟进话术（引用资料、必须人确认）、归类客户异议；不做判断性结论
- AI 在**底层**：所有原始信息先过一遍提炼管道（实体 / 分类 / 标签 + 原文片段 + 置信度），默认直接生效、人工改了即锁定；AI 只在这条管道和"话术草稿"里出现，其余流程不调模型。
- 用户路径：导入线索 → 按超时风险排序 → 推进阶段（缺必填被拦）→ 生成话术 → 保存留痕 → 仪表盘数字变化

## Rabbit holes
1. 积木过度抽象 → 6 块封顶，块内不许加"可选参数"，微调只能在模板层
2. YAML 配置失控 → 严格 schema，非法配置启动即报错
3. 提醒引擎上队列/多节点 cron → 单进程定时扫描即可
4. 话术质量不可验收 → 规则验收：引用 ≥1 条资料、必须问出下次时间、禁用"保过/保证/最低价"
5. 前端缓存业务状态 → 后端唯一真源，前端不缓存
6. 教培合规话术 → 禁用词校验（承诺效果/保过/退费承诺）

## No-gos
1. 不做 K12 学科（双减），示例只用成人职教 / 素质 / 语培
2. 不做折扣审批流（只做超阈值提醒）
3. 不做排课 / 教务 / 财务 / 退费
4. 不做微信 / 群聊抓取脚本，也不接真实短信 / 外呼；输入只来自粘贴、文本导入与人工录入
5. 不做登录 / 权限 / 多租户
6. 禁止模型判断"这单会成 / 会丢"，只提醒不下结论
7. v1 不做 LangGraph 多智能体
8. 不做 PDF（只吃 MD / TXT）
9. 不做人工逐条确认提炼结果（默认生效 + 事后可改）
10. 不做模型自动对外发消息
