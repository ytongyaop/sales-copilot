## 成本

- 假模型全链路（造数据 → 粘贴原文 → 提炼 → 生成草稿 → 确认落库）：token 固定 0，**0 元**，可无限次演示
- **ToB 演示数据本身 0 成本**（2026-11-18 实测）：`scripts/seed_demo.py` 清库造 5 条线索 / 3 条跟进 / 41 条事实 / 7 行分级留痕，
  跑完查库 `extract_runs` **0 行**、`drafts` **0 行** → **0 次模型调用、0 token、0 元**。
  原因在路径上就写死了：事实走 `set_manual`（人工补录，不调模型）、分级走 `domain/grading.py` 的规则算分（模型不参与分档），
  只有投料与话术才可能调模型，而它们不在播种流程里。
- **建索引也 0 元**（2026-11-18 实测）：`scripts/build_index.py --fake --docs-dir data\knowledge\tob` 只算本地假向量（24 chunks），
  不调 embedding API、不联网 → **0 次模型调用、0 token、0 元**。
- **一整场假模型演示（建索引 + 播种 + 投 1 次料 + 生成 1 次话术 + 看分级）合计 0 元**：全程 token 为 0（见上两条），可无限次重跑
- 真模型 20 条合成样本提炼：10776 token、18.4 秒，按 3 元/百万 token 估算 ≈ **0.032328 元**（`data/reports/extract-20261114-224019.json`；单价是估算口径，**不是账单**）
- live 单次草稿（含重试）约 600–900 token，单次约 0.002–0.003 元；2026-11-16 实测
- 月度上限：v1 没有上限控制；按上面的量级估算，一场演示（几次提炼 + 一次草稿）成本远低于 0.1 元（**估算，非实测**）
- 怎么自查：`select count(*), sum(token) from extract_runs` / `from drafts`（`data/app.sqlite3`），两列都是 0 就是没花过钱

## 已知限制

- **仪表盘阈值取默认模板**：`DashboardService.summary()` 固定用 `DEFAULT_TEMPLATE` 的阈值算 `reminders_by_level`，而 `GET /reminders` 按每条线索自己的模板算。T010 起默认模板是 `tob_enterprise`，演示库里 5 条线索全用它，所以两处一致；一旦库里混用多份模板（比如再建一条教培线索），`reminders_by_level` 会和提醒列表对不上（分模板的线索各自阈值不同）。修法（v2.1）：指标按模板分组，或明确「一屏只算默认模板的线索」。
- **回收没有后台线程**：首响超时回公海要显式触发一次（`POST /reclaim/scan` 或 `scripts/scan_reclaim.py`），不跑就不会自己发生。
- **演示数据的「红/黄/灰」依赖造数时刻**：`seed_demo.py` 用 `now - 5h / -3d / -5d` 这类相对偏移，隔一天再看时间差会变大（提醒颜色通常不变，但「已过 N 天」的数字会变）。
- **分拣单上的分级与详情页可能不同**：分拣单只按**这一条原文**抽出来的要素算档（原文没提金额就说「待补全」），详情页按该客户**全部已生效事实**算。两者口径不同是刻意的（前者提示「这条料还缺什么」），演示时要主动说明，别让人以为系统前后矛盾。
