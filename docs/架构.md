# 架构

> 用法：写"代码怎么分层、谁依赖谁"；结构变了同步改这张图，别让它变成考古资料。

## 层图

```
src/salescopilot/
├─ entrypoints/          api/ (FastAPI 路由) · bootstrap.py (唯一装配点)
├─ services/             flow · leads · followup · ingest（提炼编排）
│                        draft（话术草稿：生成 / 确认 / 丢弃）· knowledge（建索引与检索编排）
│                        dashboard（指标编排）· assignment（认领 / 释放 / 公海）
│                        reminder_service（分级提醒 + 首响超时回收）· import_service（CSV 导入）
│                        sorting（一次投料 → 分拣单）· card（信息卡读写与缺项）
│                        grading（分级提议 / 双模式 / 变更留痕）· todo（今日待办）· review（周复盘）
├─ domain/               models · blocks · rules · ports · labels · errors
│                        facts（事实生效 / 锁定 / 字段来源规则）· csv_import（CSV 解析与校验）
│                        dashboard（仪表盘指标的纯计算）· reminders（三类超时提醒）
│                        draft（草稿门槛与引用负载）· knowledge（切块与清单一致性）· eval_metrics（评测指标）
│                        assignment（归属规则）
│                        sorting（分拣判断纯规则：归属候选 / 要素覆盖）· card（四要素与覆盖度）
│                        grading（A/B/C 打分与策略参数）
├─ adapters/             db/sqlite · knowledge/（chroma_store · embedding · manifest）
│                        llm/（deepseek · fake · draft · prompts · prompts_draft）· template/loader
└─ templates/            教培.yaml · 软件外包.yaml · 建材.yaml  ← 数据，不是代码

web/                      Vue3 + Vite 前端（独立构建，只通过 HTTP 调后端）
scripts/                 seed_demo.py（造演示数据）· build_index.py（建资料索引）
                         run_eval.py（提炼基线评测）· scan_reclaim.py（首响超时一键扫描）
```

`templates/` 是配置数据目录，**不属于任何一层**；引擎不 import 它，只由 `adapters/template` 以数据方式读取。

依赖图（箭头 = import 方向，只朝一个方向）：

```
              entrypoints/
          (api · bootstrap)
             │            │
             │ import     │ import（仅 bootstrap 装配时会碰）
             v            v
        services/      adapters/
             │            │
             │            │ implements
             │            v
             └──────▶  domain/
                          ▲
                          └─ 不 import 任何其他层，不做 IO

  services ✗──import──▶ adapters     ← 这条线不允许存在
  adapters/template ──读数据──▶ templates/*.yaml
```

## 依赖方向

**只允许 `entrypoints → services → domain`；`adapters` 实现 `domain/ports.py` 的协议并由 `entrypoints/bootstrap.py` 装配；`services` 不 import `adapters`；`domain` 不 import 任何其他层、不做 IO。**

`services` 内允许互相调用**只读函数**（如 `followup` 读 `leads` 查询归属），但禁止共享可变状态——不在模块级存缓存、单例、全局变量；跨模块写入一律经 `domain` 的规则函数。`templates/` 只被 `adapters/template` 读取，任何层都不把它当 Python 模块 import。
这条规则不是口号，由 `.importlinter` 的 layers + forbidden 契约在 `lint-imports` 里锁死，出现反向依赖立即报错。

数据流：入参在 `entrypoints` 解析 → `services` 执行用例（读写一律经 `domain/ports.py` 的协议）→ `adapters` 落到 SQLite / Chroma / DeepSeek → 结果沿原路返回并格式化输出。换数据库或模型供应商，只改 `adapters/` 与 `bootstrap.py`。

## 模块职责与禁令

| `src/salescopilot/domain/` | 实体（`models.py`）、流程块契约（`blocks.py`）、必填/阈值/状态转移规则（`rules.py`）、端口协议（`ports.py`）、中文名映射（`labels.py`）、领域错误（`errors.py`）、事实规则（`facts.py`）、CSV 解析（`csv_import.py`）、指标纯计算（`dashboard.py`）、三类超时提醒（`reminders.py`）、草稿门槛与引用负载（`draft.py`）、切块与清单一致性（`knowledge.py`）、评测指标（`eval_metrics.py`）、归属规则（`assignment.py`） | 不许出现任何行业词（试听、报价单、课时、建材、证书……）；不许 import 外部 SDK（requests / openai / sqlite3 / chromadb / streamlit 等）；不许做 IO（不读文件、不发请求、不碰时钟） |

| `src/salescopilot/services/sorting.py` | 一次投料 → 分拣单编排：取原文与客户事实 → 调 LLM → 用 domain 规则校验 → 落 `sorting_batches` | 不许 import `adapters/`；不许自己实现归属 / 分级规则；不许把无原文片段的判断落库 |
| `src/salescopilot/services/card.py` | 信息卡读写：按四要素组装、算覆盖度与缺项、处理人工补录与锁定 | 不许直接写 SQL；不许覆盖人工锁定的字段 |
| `src/salescopilot/services/grading.py` | 分级提议、双模式切换、变更留痕（AI 值 / 人工值 / 原因 / 依据） | 不许原地覆盖历史分级；不许把偏好样本回写历史记录（只能影响后续打分） |
| `src/salescopilot/services/todo.py` | 今日待办编排：按分级 × 时效 × 缺项排序，组装"建议动作 + 价值点" | 不许输出没有价值点的条目；不许在排序里掺入未定义字段 |
| `src/salescopilot/services/review.py` | 周复盘：汇总推进 / 卡点 / 分级变动，收集 3 个校准问题的答案写入 `preference_samples` | 不许改历史分级或历史跟进；不许替用户自动回答校准问题 |
| `src/salescopilot/adapters/` | 端口实现：`db/sqlite.py`（全部业务表的 SQLite 仓储）、`knowledge/`（Chroma 检索 + 真/假向量 + 索引清单）、`llm/`（DeepSeek 提炼与话术适配 + 假实现 + 提示词）、`template/`（YAML 加载与校验） | 不许写业务规则（阈值判断、状态转移只能在 `domain`）；不许 import `entrypoints/` 与 `services/`；不许把行业概念硬编码进代码（行业差异只来自模板数据） |
| `src/salescopilot/templates/` | 三份行业 YAML：块的组合顺序、阈值参数、字段取值 | 不是代码，不许被任何层 import 成 Python 模块；不许在模板里塞代码或表达式；不许给块加"可选参数"式临时字段（微调只能在模板层取值，不能改块契约） |
| `web/`（仓库根，**不是** `src/` 下） | Vue3 + Vite 前端：线索列表/新增、CSV 导入、公海、提醒、事实、话术草稿、仪表盘 | 不许直接连数据库或调模型，只调后端 API；不许缓存业务状态（后端为唯一真源）；不许把必填/阈值规则复制一份到前端当权威；`/api/*` 由 Vite dev server 代理到 `127.0.0.1:8000` |

## 机制一：流程块与模板怎么组合

**块 = 数据契约，不是代码类。** 每个块只声明六项：`id` / 名称 / 进入条件（前置阶段）/ 必填输入字段 / 动作 / 出口条件。块里没有分支逻辑，也没有行业名词。v1 固定 6 个块，封顶不扩：`intake` / `first_contact` / `qualify` / `appointment` / `proposal` / `close`。

**模板 = 块的有序组合 + 阈值参数 + 字段取值。** 例如教培模板写 `first_response_minutes: 30`、包含 `appointment`（试听）；软件外包模板含方案会；建材模板跳过 `appointment`。同一份引擎代码，三份模板跑出三条不同流程。

**引擎只认五种通用概念**：阶段、字段、阈值、周期、出口条件。凡是无法归入这五种的，一律不进引擎。

- 块删掉 / 模板不引用某块时，校验器必须报错并指出位置，不静默降级成默认流程。
- 举例：把 `appointment` 块定义删除后，教培模板校验失败（它引用了试听阶段），建材模板仍然通过 —— 这就是"积木真复用"的机器证明。

## 机制二：AI 的位置与边界

AI 只有**两处**：**提炼**（raw_item → 结构化事实）与**生成**（事实 + 资料 → 话术草稿）。其余流程（推进、归属、阈值、留痕、仪表盘）一律不调模型。

- **提炼默认生效**，不要求人工确认：结果直接落库为事实，不阻塞流程，不给员工加第二道录入成本。
- **人工修改即锁定**：销售改了某字段，该字段进入人工锁定，后续提炼结果不得覆盖，直到人工解锁；字段记录来源（`llm` / `manual` / `rule`）。
- AI **不**改归属、**不**推进阶段、**不**下任何结论（不判断"这单会成 / 会丢"）、**不**自动对外发消息。话术草稿必须经人确认后才落库成为跟进留痕。

**v2 增补（ADR-0006）**：ToB 主场景下，AI 从"两处"扩为**分拣判断层** —— 归属 / 要素 / 分级 / 出库四类判断由 AI 提议，人只做投料、确认、改判。"默认生效 + 人工改即锁定"不变；AI 仍**不**自动改归属、**不**自动推进阶段，只出提议并附理由与原文依据。

强制项（每条都是测试用例，不是口号）：

| 强制项 | 含义 |
|---|---|
| schema 白名单 | 输出字段固定枚举，多出来的字段直接丢 |
| `source_span` 必填 | 每个字段必须能定位原文片段与偏移；定位不到的字段丢弃并留诊断 |
| 幂等 | 同段原文（按原文 hash）重复提炼不产生重复事实 |
| 版本留痕 | 每次调用记模型名 / prompt 版本 / 输入 hash / 输出 hash / 耗时 / token |
| 禁用词 | 话术命中承诺效果 / 保过 / 退费承诺即拦下，不落库 |

**引用的资料条目为空时拒绝生成**（返回明确的业务错误，而不是空话术）。

`pytest` 一律注入 fake 的 llm / knowledge 适配器；真实模型调用只出现在显式的在线脚本里，绝不混进默认测试。

## 数据与存储边界

业务真源是 **SQLite**：线索、跟进、阶段历史、归属事件、AI 调用记录，以及 raw_item、fact、提炼调用记录全在这里，带事务、可回溯、可回答"数字为什么变了"。**Chroma 只存产品/课程资料向量**，且**只由脚本写入**（`scripts/build_index.py`），运行时路径一律只读 —— 引擎不会在请求里改知识库。

两者的一致性靠两条规则守住：一是"索引只由脚本写、运行时只读"，业务写入永远不碰向量库；二是**索引清单记录 embedding 模型名**，换 embedding 模型必须整库重建索引，否则查询向量与旧向量不在同一空间，检索会静默变差而没人发现。

| 存什么 | 位置 | 谁写 | 谁读 | 一致性规则 |
|---|---|---|---|---|
| 线索 / 跟进 / 阶段历史 / 归属事件 / AI 调用记录 | SQLite | 只有 `adapters/db`（由 `services` 发起） | `services` | 后端为唯一真源，前端不缓存；换库只换 adapter |
| `assignment_events`（归属变更：从谁到谁 / 原因 / 时间） | SQLite | 只有 `adapters/db`（认领、释放、自动回收由 `services` 发起） | `services`、运行排查 | 只追加不改写；`reason` 只取 `ALLOWED_ASSIGNMENT_REASONS`（claim / release / auto_reclaim / manual） |
| raw_item（原始信息原文） | SQLite | 采集服务 | 提炼、回查 | 只追加不改写 |
| fact（结构化事实：字段 / 值 / 来源 / 原文片段 / 置信度 / 锁定标志） | SQLite | 提炼与人工 | 流程、话术、仪表盘 | 人工锁定后 AI 不得覆盖 |
| 提炼调用记录（模型 / prompt 版本 / 输入输出 hash / 耗时 / token） | SQLite | 提炼服务 | 排查、漂移对比 | 只追加 |
| `sorting_batches`（分拣单：来源原文 / 归属提议 / 补的要素 / 分级变化 / 出库建议 / 人的操作） | SQLite | 分拣编排服务（`services/sorting`） | 分拣台、客户详情、排查 | 只追加不改写；人的操作（同意 / 改归属 / 改分级 / 忽略）另起一行留痕，不覆盖原单 |
| `grading_history`（分级变更：AI 建议值 / 人工最终值 / 差异原因 / 依据片段 / 操作人 / 时间） | SQLite | 分级服务（`services/grading`） | 分级展示、周复盘、审计 | 只追加；改判必须写一行，不许原地覆盖 |
| `preference_samples`（校准样本：复盘问题 / 使用者回答 / 抽出的偏好） | SQLite | 复盘服务（`services/review`） | 后续分级打分、复盘 | 只追加；样本只影响权重与阈值，不许回改历史分级 |
| 资料原文（MD / TXT） | 资料目录（不进业务库） | 人工放入 | 索引脚本 | 原文为准，索引随时可重建 |
| 资料向量 + 索引清单（含 embedding 模型名） | Chroma | 只有索引脚本 | `adapters/knowledge`（只读） | 换 embedding 模型必须重建索引；清单模型名与当前配置必须一致 |
