# ADR-0007：归属用确定性漏斗，向量只做召回

- **状态**：已接受
- **日期**：2026-11-18
- **背景**：v1 与 v2 初稿把"这票货算哪家客户"交给 LLM 一次判断（初稿里还有个 0.7 的单一置信阈值），但归属错误的代价与别的判断不同级 —— 要素抽错可以补，分级判错可以改判，**归属错了就是把 A 客户的话、金额、决策人写进 B 客户的信息卡**，两家客户的历史被永久污染，且事后人工无从分辨哪些字段原本属于谁。同时 LLM 给出的"归属 + 置信度"不可复现、不可解释：同一段文本换一次调用分数就变，阈值调到多少也没有依据。客户名在真实投料里又高度不规整（繁简混用、"华远"与"华远建设集团"、全角括号、同名不同公司），单靠字符串相等必然漏配，单靠向量又必然串号。
- **选项**：
  - A：**LLM 直接判定归属**（初稿做法）—— 代码最省，但不可复现、不可审计，错分无法定位；置信度自评没有校准口径，"0.7" 是拍脑袋。
  - B：**纯规则匹配**（只做精确键 + 字符串相似）—— 完全确定、可测，但中文简称 / 别名 / 口语写法一多就大量漏配，全都掉进人工队列，等于把判断负担还给人。
  - C：**三级确定性漏斗 + 灰区 LLM 复核**（本次所选）—— 规范化 → L0 精确键 → L1 字符串相似 → L2 向量相似，逐级短路；只有灰区（候选 ≤3）才让模型复核，且模型只排序、不创造候选；所有判定写审计日志。代价是多一层规范化与阈值维护，还需要一批标注样本。
- **决策**：选 **C**。具体口径：
  - ① **规范化**：繁→简、全角→半角、去「有限公司 / 股份 / 集团 / 分公司」等后缀、去括号内容、查别名表（别名表放模板，不写进代码）。
  - ② **L0 精确键**：手机号 / 邮箱 / 统一社会信用代码 / 规范化全称，命中即归属（`scorer='exact'`，不打分、不调模型）。
  - ③ **L1 字符串**：rapidfuzz `token_sort_ratio` + Jaro-Winkler（0–100）；**≥95 且有第二字段佐证（地区 / 行业 / 联系人）→ 自动；85–95 → 进人工队列；<85 → 下探 L2**。
  - ④ **L2 向量**：沿用现有百炼 `text-embedding-v3` 算 cos；**≥0.92 且有佐证 → 自动；0.80–0.92 → 人工；<0.80 → 视为新客户**；**向量永不单独授权合并**。
  - ⑤ **灰区复核**：只在候选 ≤3 时调 LLM 复核，模型只能在既有候选里排序，不能凭空产出客户。
  - ⑥ **阈值不拍脑袋**：所有阈值从模板读，由 `scripts/calibrate_thresholds.py` 用 50 对人工标注样本扫 precision / recall 曲线产出；校准报告落 `data/reports/`。
  - ⑦ **审计**：每次归属写 `scorer` / `score` / `threshold` / 候选列表，能回答"为什么算到这家"。
- **后果**：
  - 变好：归属可解释、可审计、可回归测试（同一输入同一结果）；错分的影响面从"污染客户档案"收窄为"多一次人工确认"；向量从"决策者"降级为"召回器"，串号风险被 L1 佐证与人工带双重兜住；阈值有曲线支撑，调松调紧都能说出代价。
  - 变差：多一层规范化与别名表维护（新客户别名要人补，否则会漏配）；灰度带（L1 85–95 / L2 0.80–0.92）会让人工队列变长，短期内"多点几下"；阈值随样本分布漂移，需要定期重跑校准。
  - 要还的债 / 代价：需要一批 50 对标注样本（纯人工投入，不占开发工时）；归属链路的工时从 13h（T002 5h + T003 8h）增至 20h（T002 8–10h ＋ T002b 3h ＋ T003 9h），**总工时 66h → 73h（+7h）**；模板多一段 `matching:` 阈值与别名表，模板校验器要跟着长。
- **确认方式**：AC-10（精确键命中不调模型，断言 judge 调用计数为 0 且审计 `scorer=exact`）、AC-11（L1 85–95 无佐证 → 进人工队列，`lead_id` 为空）、AC-12（模型给出原文里不存在的出处片段 → 该字段被丢弃并记 `span_misaligned`，用例可复现地失败于旧实现）；50 对样本的校准报告（precision / recall 曲线 + 选定阈值）落入 `data/reports/matching_calibration.md`；审计日志字段（`scorer` / `score` / `threshold` / `candidates[]`）在 `sorting_batches.match_audit` 里逐条可查。
