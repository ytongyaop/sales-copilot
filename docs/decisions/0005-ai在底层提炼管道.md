# ADR-0005：AI 提为底层提炼管道

- **状态**：已接受
- **日期**：2026-11-14
- **背景**：原始信息太碎 —— 客户信息、群聊、微信、电话记录散在各处，靠人填不进来，台账最后只剩"已联系"。AI 若只做"写话术"，就只是装饰：话术再好，前提（信息在库里）不成立。同时公司层要的是客户资产，而人一走客户就没了，过程看不见、无法交接。
- **选项**：
  - A：AI 作为**输入提炼层** —— 采集原始信息 → LLM 提炼成结构化事实（带原文片段与置信度）→ 默认直接生效，人工修改即锁定该字段
  - B：AI 只做话术与异议归类，信息仍靠人填 —— 录入成本不变，数据照样不全，AI 价值停留在装饰
  - C：AI 提炼 + 人工逐条确认 —— 等于给员工加第二道录入成本，摧毁"员工愿意用"这个前提
- **决策**：选 A。AI 放在底层输入侧：从 raw_item 提炼实体 / 分类 / 标签，每条带 `source_span` 与 `confidence`，无原文片段的字段丢弃；结果**默认生效、不要求逐条确认**，人工一改该字段即锁定，后续 AI 不得覆盖。AI 只出现在"提炼"与"话术草稿"两处，其余流程不调模型。
- **后果**：
  - 变好：录入从"写"变成"改"，员工侧的摩擦被压到最低，数据才可能全；每条事实可回查原文片段，默认生效也追得回责任；公司层因此第一次拿得到可复用的客户资产。
  - 变差：需要上下文管理（按客户组织、滚动摘要）与漂移监测；存在模型误提炼风险 —— 靠"原文片段必填 + 幂等（原文 hash）+ 版本留痕（模型 / prompt 版本 / 输入输出 hash）"三条约束把它压到可接受。
  - 要还的债 / 代价：v1 增加约 8–10h，必须砍掉抓取脚本等范围；更精细的上下文压缩策略（效仿开源 agent 的做法）下阶段调研，v1 先用"摘要 + 事实 + 最近若干条原文"。
- **确认方式**：提交一段含"价格太贵、还要再考虑"的原文 → 提炼出"异议 = 价格""意向 = 待定"且每条带原文片段；构造无法定位原文的输出 → 字段被丢弃并留诊断；同段原文连跑两次 → 事实条数不变；人工把异议改成"效果"后再跑提炼 → 仍为"效果"，解锁后可被覆盖。
