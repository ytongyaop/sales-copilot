# ADR-0001：引擎 + 流程块 + 模板 三层分层

- **状态**：已接受
- **日期**：2026-11-13
- **背景**：v1 只有一周 50 小时，却要交付一个能演示"换行业不改代码"的流程引擎。三份模板（教培 / 软件外包 / 建材）流程不同但骨架相似：都是"拿到线索 → 首联 → 筛意向 → 约见/试听 → 出方案 → 成交或放弃"。必须决定行业差异到底写在哪一层，否则"可迁移"只是口号。
- **选项**：
  - A：引擎（唯一代码）+ 6 个流程块（intake / first_contact / qualify / appointment / proposal / close）+ 行业模板三层 —— 差异只进模板
  - B：每个行业写一份完整流程配置，不做块抽象 —— 改一处要改三遍，三份配置会悄悄分叉
  - C：每个行业一份独立代码分支 —— 最贵，一周时间装不下
- **决策**：选 A。引擎只认"阶段 / 字段 / 阈值 / 周期 / 出口条件"五种通用概念，块的顺序与参数全部来自模板 YAML。
- **后果**：
  - 变好：换行业只改模板；三份模板共用同一份引擎代码，变更点收敛为一个；`appointment` 被教培用、被建材跳过，复用可被机器证明。
  - 变差：块间契约（进入条件 / 必填字段 / 出口条件）必须先在 `domain/blocks.py` 里设计好，前期比"直接写流程"多花时间；存在过度抽象风险，因此**6 块封顶**，块内不许加"可选参数"，微调只能在模板层取值。
  - 要还的债：若出现第 7 类流程，只能改块契约而不是加块，必须重新评审一次。
- **确认方式**：删掉 `appointment` 块定义后，教培模板校验失败、建材模板仍然通过；新增一张模板不改 `src/` 也能启动。
