# ADR-0004：引擎代码不含行业词

- **状态**：已接受
- **日期**：2026-11-13
- **背景**：整个方案卖的是"换行业不改代码"。如果引擎里出现"试听、报价单、课时、建材、证书"这类词，换行业就得改代码，可迁移性退化成一句宣传语；更糟的是这类词会慢慢渗进规则判断，谁也说不清它该留在哪。需要一个不靠自觉、能机器验证的边界。
- **选项**：
  - A：引擎代码禁用行业词，用 `grep` 做自动化验收
  - B：命名上贴近业务（如"排试听课""出报价单"）—— 读起来更顺，但迁移时改代码，且"可迁移"无法被验证
- **决策**：选 A。行业概念只允许出现在 `templates/*.yaml`（作为块取值与阈值参数）与 `web/` 的展示文案；`domain/` 与 `services/` 一律使用通用词（阶段、字段、阈值、周期、出口条件）。
- **后果**：
  - 变好：可迁移性变成一条可执行命令，输出为空即通过；新人一眼看出某个词属于模板而不是引擎；块契约不会被某个行业的习惯悄悄改写。
  - 变差：每加一个行业概念，必须先判断它属于"块契约"还是"模板取值"，多一步判断；引擎命名更抽象（如 `stage`、`required_fields`），初读不如业务命名直观。
  - 要还的债：禁用词表要维护，出现新行业词先补进 `grep` 命令，否则验收会漏。
- **确认方式**：对引擎目录跑 `grep -ri "试听|报价单|课时|建材|证书|保过" src/salescopilot/domain src/salescopilot/services`，没有任何输出。
