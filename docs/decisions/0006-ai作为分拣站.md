# ADR-0006：AI 作为分拣站，人只做投料 / 确认 / 改判

- **状态**：已接受
- **日期**：2026-11-17
- **背景**：v1 已交付（247 条测试全绿），但验收后暴露三个问题：①前端结构混乱，功能之间不结合；②看不出模型的作用；③大量手操，像个收集表。根因是 v1 把 AI 放在**输入侧（提炼）与末端（话术）**，中间整条判断链仍留给人 —— 这条信息归谁、补了哪个要素、这家该不该优先、今天先打给谁，全要人自己想、自己填。AI 因此只省了"打字"，没省"判断"，人一天的精力仍花在整理与排序上，而不是花在客户身上。ToB 场景下单笔金额大、决策链多人、周期数周到数月，判断密度更高，这个问题更尖锐。
- **选项**：
  - A：继续加录入界面（字段更多、表单更细）—— 录入成本继续上升，等于把"收集表"做得更精致，问题 ③ 恶化
  - B：AI 只做辅助建议（提示一下，判断仍由人做完）—— 人的判断负担不降，AI 仍是装饰，问题 ②③ 不变
  - C：AI 承担判断层，人只做确认与改判 —— 人的动作从"填"变"确认"，产品形态从表单变成分拣站；代价是分级策略、校准机制与前端的重构
- **决策**：选 C。AI 做**四类判断**：归属（这票货算哪家）/ 要素（补了信息卡四要素里的哪项，带原文片段）/ 分级（A/B/C + 理由 + 依据）/ 出库（建议下一步：动作 + 时间 + 给什么价值）。人只做三件事：**投料、确认、改判**，不做录入。沿用 v1 已确立的**"默认生效 + 人工改即锁定"**原则：AI 判断默认直接生效（模式一可改为"人确认后入库"），人一改就以人工值为准，AI 不得覆盖，直到人工解锁；每次判断必须带理由与原文依据，分级变更只追加留痕（AI 建议值 / 人工最终值 / 差异原因）。
- **后果**：
  - 变好：人的动作从"填"变"确认"，单次交互从"想 + 写"降为"看一眼 + 点一下"；模型的作用第一次直接可见（每张分拣单都写着它判断了什么、凭什么）；前端从"功能堆叠"收敛为四个区（投料口 / 分拣站 / 货架 / 出库口），功能之间由分拣单串起来。
  - 变差：需要一套分级策略与校准机制（默认权重 + 每周 3 问的偏好样本），否则分级会退化成拍脑袋；**判断错误会误导资源分配** —— 把 C 判成 A 就是白花时间，靠"理由 + 依据片段 + 变更留痕 + 三列对照"把错误压到可发现、可纠正，而不是靠模型保证不出错。
  - 要还的债 / 代价：v2 前端需重构（五入口：分拣台 / 客户 / 客户详情 / 复盘 / 设置），v1 的前端页面不保证保留；分级与校准是新增模块，需要新的数据表（sorting_batches / grading_history / preference_samples）；"AI 只在提炼与话术两处"的旧边界作废，架构文档与 PRD 需同步更新。
- **确认方式**：F13–F19 的验收判据逐条可观察（投一段对话 → 分拣单正确归属并补上至少 1 个要素且带原文片段；信息卡缺项给出"缺什么 + 下次问什么"；分级带理由与依据片段；人工改判后三列留痕；今日待办无空建议；无价值跟进可识别；复盘列出本周分级变动与卡点）；同时 `pytest -q` 全绿（v1 的 247 条不回归），契约测试与行业词测试（`tests/test_no_industry_words.py`）继续通过 —— 分拣判断的规则进 `domain/`，行业词仍只留在模板与前端。
