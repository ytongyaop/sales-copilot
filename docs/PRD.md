# PRD

> 用法：需求基线。只写"要什么"，不写"怎么做"；改方向先改这里，再改 specs。

## 目标用户

中小企业的销售负责人与一线销售（4–10 人团队）。两层角色，顺序不能反：

- **员工层（前提）**：一线销售 —— 每天登记线索、跟进、写结论的人，也是主要使用者。信息太碎：客户信息、群聊、微信、电话记录散在各处，整理和管理都费劲。**员工必须觉得省事，才会持续维护信息**；否则没人会把客户主动交出来。
- **公司层（买单理由）**：销售负责人 / 老板 —— 看过程、看卡点、决定谁的线索要收回的人。**客户被销售捏在自己手里，等于公司没有客户资产**：人一走客户就没了，过程看不见、无法交接、无法度量。

> 使用者是员工，买单的是公司；但只有先把员工层的成本降到"愿意用"，公司层的数据才会出现 —— 顺序反过来（先逼员工填）历史上都失败。

## 要解决的问题

1. **员工层**：信息太碎，整理成本高于收益，于是台账只剩"已联系"。
2. **公司层**：客户资源私有化，公司拿不到可复用的客户资产。

> 关系：先把员工层的成本降到"愿意用"，公司层才可能拿到数据。反过来做（先逼员工填）历史上都失败。

## AI 在这个系统里做什么（三层管道）

AI 处在**输入侧**，不是输出侧的装饰。一条信息进系统要走三层：**采集 → 提炼 → 生效**。

- **① 采集**：原始信息进来（粘贴文本 / 导入文本文件 / 人工录入），存为 **raw_item**（原文 + 来源 + 时间 + 归属客户）。**这一层不过模型**，原样留存，谁都能回查。
  - 明确不做：微信 / 群聊抓取脚本（合规与封号风险，见"明确不做"）。
- **② 提炼（结构化事实的入口）**：输入"一段原文 + 该客户的事实摘要"，输出固定 JSON：实体（客户 / 联系人 / 意向）、分类（异议类型）、标签。每条字段必须带 `source_span`（原文片段及起止偏移）与 `confidence`。
  - **没有 `source_span` 的字段一律丢弃**（不许凭印象编）。
  - 幂等：同段原文（按原文 hash）重复提炼不产生重复事实。
  - 留痕：记录模型名、prompt 版本、输入 hash、输出 hash。
- **③ 生效**：提炼结果**默认直接落库生效**（不阻塞流程、不要人工逐条确认）。销售可随时修改；**修改后该字段进入人工锁定，后续 AI 结果不得覆盖，直到人工解锁**。每个字段记录来源（`llm` / `manual` / `rule`）。

一句话总结：**采集不过模型；结构化事实由提炼补齐；分拣判断由 AI 提议、人来确认；生效默认自动、人工一改就锁。**

### 为什么不需要人工确认

逐条确认等于给员工加第二道录入成本，会摧毁"员工愿意用"这个前提。默认生效 + 事后可改，才是低摩擦且可追责的做法 —— 因为每条都带原文片段，可回查。

### 上下文怎么管

上下文按**客户**组织，不按会话：同一个客户的信息散落在多段原文里，只有并到一处才有用。

三层记忆：

| 层 | 存什么 | 用途 |
|---|---|---|
| 原始条目（全量） | raw_item，只追加、不改写 | 回查、重新提炼 |
| 滚动摘要 | 按客户累积的摘要 | 压上下文长度 |
| 已生效事实 | fact（含锁定标志） | 流程、话术、仪表盘的唯一结构化输入 |

喂给模型的是"摘要 + 事实 + 最近若干条原文"，不是全量原文。

> 更精细的压缩策略（效仿开源 agent 的上下文压缩做法）**下阶段调研，不阻塞 v1**。

## 功能清单（v1 最小可用）

- [x] F1 线索入库：能手动新建一条线索，也能导入一份 CSV，每条线索带来源与归属人，导入后立刻在列表里看到。（表单 + `POST /leads`、文件导入 + `POST /leads/import`，同联系方式幂等跳过）
- [x] F2 模板加载与校验：系统能加载三份行业模板（教培 / 软件外包 / 建材）；模板配置不合法时启动即报错并指出哪一处不合法，不静默降级成默认流程。
- [x] F3 阶段推进：线索只能按模板定义的顺序推进；当前阶段必填项缺失时推进被拦住，并明确提示缺哪几项。（**必填字段可由人工补录或由提炼自动补齐**；前者走 `PATCH /leads/{id}/fields` + 前端「补字段」小表单，后者在提炼落库后按事实自动补缺、不覆盖已填值）
- [x] F4 归属与回收：每条线索归属到具体的人；首次联系超时后线索自动回到公海，其他人可以重新认领并看到它已回收。（回收由显式扫描触发：`POST /reclaim/scan` / `scripts/scan_reclaim.py`，无常驻定时器）
- [x] F5 阈值提醒：系统按模板阈值提示三类时限 —— 首次响应、到访后反馈窗口、无下次跟进时间；阈值在模板里可改，改完提醒口径随之变化。
- [x] F6 跟进留痕：每次跟进必须同时记录「结论 + 客户异议 + 下次跟进时间」三要素，缺任一项保存被拒并说明缺哪项。
- [ ] F7 原始信息采集：能把一段粘贴文本或一个文本文件存为 raw_item，并挂到指定的客户上。（粘贴已完成；**文本文件选读未做**，v1.1）
- [x] F8 提炼管道：对 raw_item 提炼出实体 / 异议分类 / 标签，每项带原文片段与置信度；无原文片段的字段不落库；同段原文重复提炼不产生重复事实；每次提炼记录模型与 prompt 版本。
- [x] F9 事实生效与锁定：提炼结果默认直接生效；销售修改某字段后该字段锁定，后续提炼不得覆盖；字段上显示来源（AI / 人工 / 规则）。
- [x] F10 话术草稿：基于已生效事实 + 资料引用生成跟进话术；引用为空拒绝生成；必须人工确认才落库为跟进记录；命中禁用词不落库。
- [ ] F11 仪表盘：能看到四个数字 —— 24 小时首联率、到访反馈及时率、无下次跟进时间的线索占比、沉默线索数；数据变化与操作时间对得上。（已做 3 个：24h 首联率 / 无下次跟进占比 / 沉默线索数，另有总数、公海、本周新增与跟进；**到访反馈及时率未做**，v1.1）
- [x] F12 三份模板：教培（含试听，主演示）、软件外包（含方案会）、建材（跳过邀约）三份模板都能跑通；6 个块中有 5 个被 2 份以上模板复用（`appointment` 仅教培 / 外包使用）。

> 产品价值不等于"AI 会写话术"。普通信息平台的最大死因是录入成本；AI 的价值是**把录入从"写"变成"改"**（提炼默认生效 + 人工修正），并把散落的原始信息变成可追溯的结构化事实。

### 明确不做

1. 不做 K12 学科（双减），示例只用成人职教 / 素质 / 语培
2. 不做折扣审批流（只做超阈值提醒）
3. 不做排课 / 教务 / 财务 / 退费
4. **不做微信 / 群聊抓取脚本，也不接真实短信 / 外呼**；输入只来自粘贴、文本文件导入与人工录入
5. 不做登录 / 权限 / 多租户
6. 禁止模型判断"这单会成 / 会丢"，只提醒不下结论
7. v1 不做 LangGraph 多智能体
8. 不做 PDF（只吃 MD / TXT）
9. **不做人工逐条确认提炼结果**（默认生效 + 事后可改）
10. 不做模型自动对外发消息

## 成功判据（可测）

- [ ] 跑 `pytest -q` 全绿，且打开 `/docs` 能看到接口文档。
- [ ] 主链演示：导入线索 → 超时那条在列表里标红 → 推进阶段（缺必填被拦住）→ 采集一段原文并提炼 → 生成话术（带资料依据）→ 保存留痕 → 仪表盘数字发生变化。
- [ ] 引擎不含行业词：跑 `pytest -q tests/test_no_industry_words.py` 全绿（词表在 `tests/fixtures/industry_words.txt`，pytest 与人工 grep 共用同一份清单）。
- [ ] 积木真复用：三份模板校验全部通过；把 appointment 块删掉后，教培模板校验失败、建材模板仍然通过。
- [ ] 留痕强制：结论 / 异议 / 下次跟进时间三要素缺任意一项，保存请求被拒绝。
- [ ] 合规兜底：生成的话术里出现"保过 / 保证提分"一类说法时被拦下，不落库。
- [ ] 失败不白屏：把后端停掉，前端显示看得懂的业务语言错误，而不是空白页或原始报错。
- [ ] 提炼可用：粘贴一段含"价格太贵、还要再考虑"的对话 → 提炼出"异议 = 价格""意向 = 待定"，且每条都带原文片段。
- [ ] 无据不落库：构造一条无法定位原文的提炼输出 → 该字段被丢弃，并留下诊断记录。
- [ ] 幂等：同一段原文连续提炼两次 → 事实条数不变。
- [ ] 人工锁定：把"异议"改成"效果"后再跑一次提炼 → 该字段仍是"效果"；解锁后再提炼 → 可被覆盖。
- [ ] 禁用词：话术草稿含"保过 / 保证提分"时不落库。

## 约束

- 时间：一周 7×8 ≈ 50 小时，超时砍功能不延期（砍单顺序见 pitch 的 Appetite）。
- 运行环境：本地单机运行，不做部署编排。
- 外部服务：对话模型用 DeepSeek，embedding 用百炼。
- 技术栈约束：后端 FastAPI，前端 Vue3；业务数据存 SQLite，知识库用 Chroma。
- 合规：教培场景禁用承诺效果 / 保过 / 退费承诺类话术。
- 数据：只吃 MD / TXT 资料，不做 PDF 解析。
- AI 只在**四类分拣判断**里的**归属复核 / 要素抽取 / 出库建议**三块与**话术生成**中出现；**分级由规则主算，模型只做抽取与解释**（ADR-0008），其余流程不调模型。
- 提炼必须可回放：模型名 + prompt 版本 + 输入 / 输出 hash 记入数据库。

## v2：分拣中转站（ToB 主场景）

> 一句话：**大模型做分拣站，人只负责把信息塞进去，分拣站分拣。** 人只做三件事：**投料、确认、改判 —— 不做录入。**

v1 把 AI 放在输入侧与末端（提炼、话术），判断链仍留给人，用起来像一张"收集表"：人要自己决定这条信息归谁、补了哪个要素、这家该不该优先、今天先打给谁。v2 把这四类判断交给 AI 提议，人只审结果。决策记录见 `docs/decisions/0006-ai作为分拣站.md`。

### 1. 目标用户（v2 修订）

- **客户画像**：中小企业 ToB 销售团队（4–10 人），单笔金额较大、决策链多人、周期数周到数月。v2 的主场景是这类团队，不是教培一对一。
- **员工层痛点**：**时间花在整理信息与判断优先级上，不是花在客户身上**；台账最后只剩"已联系"三个字。
- **公司层痛点**：客户资源在个人手里，人一走就没了；过程不可见，无法交接、无法度量；分级靠感觉，资源投放凭印象。
- **范围声明**：**v2 不做 ToC**。v1 的教培模板保留为**第二模板**，只用于证明"同一引擎可跑不同行业"，不再作为主演示路径；不删、不专门为它做界面。

### 2. 产品形态：四个区

```
① 投料口   任意原始信息（粘贴文本 / 文件 / Excel / 会议纪要）
② 分拣站   四个判断：归属 / 要素 / 分级 / 出库（分级由规则主算，模型只做抽取与解释）
③ 货架     客户按 A/B/C 摆放；每家一张信息卡（四要素）+ 时间线
④ 出库口   今日待办 / 话术草稿 / 周复盘
```

**人只做投料、确认、改判 —— 不做录入。**

| 区 | 人做什么 | AI 做什么 | 对应功能 |
|---|---|---|---|
| ① 投料口 | 把原文粘进来 / 传文件，选或不选客户 | 无（原文原样留存，不过模型） | F13 |
| ② 分拣站 | 看一眼、点同意 / 改判 | 四个判断 + 理由 + 原文依据 | F14 / F16 |
| ③ 货架 | 翻卡片、补一句话 | 维护四要素覆盖度、标缺项 | F15 / F16 |
| ④ 出库口 | 按建议做事、写完跟进 | 排序、起草、汇总 | F17 / F18 |

### 3. 分拣单（v2 的核心交互）

每投一次料，产出**一张分拣单**。它是人和 AI 之间唯一的交接物：AI 把判断摆出来，人只做四个动作之一。

| 字段 | 内容 | 人能否改 |
|---|---|---|
| 归属客户 | 这票货算哪家（可新建） | 能（改归属） |
| 补充了哪一要素 | 四要素里补了哪项、补成什么，**必须带原文片段** | 不能（只能忽略整单） |
| 分级变化 | 原级别 → 新级别 + 理由 + 依据片段 | 能（改分级） |
| 建议下一步 | 动作 + 时间 + **给什么价值** | 不能（可忽略） |
| 四个操作 | 同意 / 改归属 / 改分级 / 忽略 | —— |

```
┌─ 分拣单 #S-0127 ────────────────── 2026-11-17 14:20 ─┐
│ 来源：粘贴 · 客户电话纪要（8 分钟）                     │
│                                                       │
│ ① 归属   华远建设（置信 0.92）                          │
│          依据："我们下周三和采购部对一下预算"            │
│          操作：[同意] [改归属] [忽略]                    │
│                                                       │
│ ② 要素   补上「决策流程与预算 · 采购方式 = 公开招标」     │
│          原文："走公开招标，标书下月发"                  │
│          覆盖度：5/8 → 7/8                             │
│                                                       │
│ ③ 分级   B → A                                         │
│          理由：预算明确 + 决策人已露面 + 30 天内动手      │
│          依据：3 条原文片段（可展开）                     │
│          操作：[同意] [改分级] [忽略]                    │
│                                                       │
│ ④ 出库   下一步：周五前发《同类项目验收清单》             │
│          给什么价值：帮客户把标书要求写清楚              │
│                                                       │
│ 操作：[同意入库] [改归属] [改分级] [忽略]                │
└───────────────────────────────────────────────────────┘
```

规则：

- 一张单只做**一次**投料对应的判断，不合并多段原文（避免"改了一半不知道改的是哪句"）。
- 「同意」后要素与分级落库；「忽略」整单作废但**原文仍留存**，可重新投料。
- 分拣单本身只追加，不原地改写；人的改判以新记录留痕。

### 4. 客户分级（三层设计）

**第一层：默认策略（可配置）**

| 维度 | 默认权重 | 看什么 |
|---|---|---|
| 成交金额 | 30% | 预算区间 / 单笔规模 |
| 紧迫度 | 30% | 有无明确时间点、卡在谁那里 |
| 决策清晰度 | 20% | 决策链是否清楚、关键人是否已接触 |
| 需求匹配度 | 20% | 痛点与我方能力的重合度 |

权重写在模板/配置里，不写死在代码；改权重不改判定逻辑。分级只表示"该投多少资源"，**不是成交概率预测**。

**第二层：个性化校准**

每周复盘时向使用者问 3 个问题，答案记成"偏好样本"，用于调权重与阈值：

1. 哪家你从 B 提到了 A？为什么？
2. 哪家标了 C 但你没放弃？为什么？
3. 哪一次 AI 判断错了？错在哪？

样本只影响后续打分，**不许回改历史分级**。

**第三层：两种模式**

- **`AI 提议 + 人确认入库`（默认）**：分拣单给出建议，人点同意才落库。
- **`AI 直接定 + 变更留痕 + 人可追溯修改`**：AI 判定直接生效，但每次变更都留痕，人可随时改并写原因。

两种模式都必须记录三列：**AI 建议值 / 人工最终值 / 差异原因**。分级变更有历史：**谁改的、什么时候、依据是什么**（依据可以是原文片段或复盘回答）。

### 5. 客户信息卡（ToB 四要素）

| 要素 | 字段 | 缺失时的行为 |
|---|---|---|
| 基础信息 | 公司、行业、规模、关键联系人（决策者 / 影响者 / 使用者）、组织架构 | 卡片标"缺基础信息"，今日待办提示"先确认决策者是谁"，不阻止其他要素继续补 |
| 需求与痛点 | 核心问题、痛点强度、我方匹配点 | 标"需求未明"，分级的需求匹配度记 0 分并在理由里写明"缺需求信息"，不许猜 |
| 决策流程与预算 | 决策链、关键节点、预算区间、采购方式 | 标"决策链不明"，建议动作改为"问清谁签字、什么时候定" |
| 跟进记录 | 每次的要点 / 客户承诺 / 下一步 / **本次提供的价值** | 「本次提供的价值」为空时，该次跟进标记为**无价值跟进**（对应方法论里的"避免催单"） |

- 每项带**来源片段**与**来源**（`AI` / `人工`），和 v1 的字段来源规则一致：人工改过的字段锁定，AI 不覆盖。
- 卡片顶部显示**覆盖度**（已填项 / 总项）与**缺项清单**；缺项清单要能直接变成下一次该问的问题。

> 「本次提供的价值」为空即"无价值跟进"：只催进度、没给东西。系统不骂人，但要让它可见 —— 这是"避免催单"落到产品上的唯一抓手。

### 7. v2 明确不做
