# PRD

> 用法：需求基线。只写"要什么"，不写"怎么做"；改方向先改这里，再改 specs。

## 目标用户

中小企业的销售负责人与一线销售（4–10 人团队）。

- 一线销售：每天登记线索、跟进、写结论的人，是主要使用者。
- 销售负责人：看过程、看卡点、决定谁的线索要收回的人。
- 使用者是员工，买单的是公司 —— 所以第一价值是"员工愿意天天填"，不是"老板看到报表"。

## 要解决的问题

中小企业的销售流程各不相同，买标准 CRM 装不进自己的流程，找人定制又贵又改不动。现状是 Excel + 微信 + 口头规则：线索靠人记、过程看不见、换个人就断档。

## 功能清单（v1 最小可用）

- [ ] F1 线索入库：能手动新建一条线索，也能导入一份 CSV，每条线索带来源与归属人，导入后立刻在列表里看到。
- [ ] F2 流程模板加载：系统能加载三份行业模板（教培 / 软件外包 / 建材）；模板配置不合法时启动即报错并指出哪一处不合法，不静默降级成默认流程。
- [ ] F3 阶段推进：线索只能按模板定义的顺序推进；当前阶段必填项缺失时推进被拦住，并明确提示缺哪几项。
- [ ] F4 归属与回收：每条线索归属到具体的人；首次联系超时后线索自动回到公海，其他人可以重新认领并看到它已回收。
- [ ] F5 阈值提醒：系统按模板阈值提示三类时限 —— 首次响应、到访后反馈窗口、无下次跟进时间；阈值在模板里可改，改完提醒口径随之变化。
- [ ] F6 跟进留痕：每次跟进必须同时记录「结论 + 客户异议 + 下次跟进时间」三要素，缺任一项保存被拒并说明缺哪项。
- [ ] F7 AI 话术草稿：能为某条线索生成一段跟进话术，话术里带出引用的资料原文；引用为空时拒绝生成；生成结果必须人工确认后才落库生效。
- [ ] F8 异议归类：能把客户异议归入一组固定分类，销售可手动改正；系统不对"这单会成/会丢"给出结论。
- [ ] F9 仪表盘：能看到四个数字 —— 24 小时首联率、到访反馈及时率、无下次跟进时间的线索占比、沉默线索数；数据变化与操作时间对得上。
- [ ] F10 三份模板：教培（含试听，主演示）、软件外包（含方案会）、建材（跳过邀约）三份模板都能跑通；6 个块中有 5 个被 2 份以上模板复用（`appointment` 仅教培/外包使用）。

### 明确不做

1. 不做 K12 学科（双减），示例只用成人职教 / 素质 / 语培
2. 不做折扣审批流（只做超阈值提醒）
3. 不做排课 / 教务 / 财务 / 退费
4. 不接真实短信 / 微信 / 外呼，AI 只出草稿
5. 不做登录 / 权限 / 多租户
6. 禁止模型判断"这单要凉"，只提醒不下结论
7. v1 不做 LangGraph 多智能体
8. 不做 PDF（只吃 MD/TXT）

## 成功判据（可测）

- [ ] 跑 `pytest -q` 全绿，且打开 `/docs` 能看到接口文档。
- [ ] 主链演示：导入线索 → 超时那条在列表里标红 → 推进阶段（缺必填被拦住）→ 生成话术（带资料依据）→ 保存留痕 → 仪表盘数字发生变化。
- [ ] 引擎不含行业词：跑 `pytest -q tests/test_no_industry_words.py` 全绿（词表在 `tests/fixtures/industry_words.txt`，pytest 与人工 grep 共用同一份清单）。
- [ ] 积木真复用：三份模板校验全部通过；把 appointment 块删掉后，教培模板校验失败、建材模板仍然通过。
- [ ] 留痕强制：结论 / 异议 / 下次跟进时间三要素缺任意一项，保存请求被拒绝。
- [ ] 合规兜底：生成的话术里出现"保过 / 保证提分"一类说法时被拦下，不落库。
- [ ] 失败不白屏：把后端停掉，前端显示看得懂的业务语言错误，而不是空白页或原始报错。

## 约束

- 时间：一周 7×8 ≈ 50 小时，超时砍功能不延期（砍单顺序见 pitch 的 Appetite）。
- 运行环境：本地单机运行，不做部署编排。
- 外部服务：对话模型用 DeepSeek，embedding 用百炼。
- 技术栈约束：后端 FastAPI，前端 Vue3；业务数据存 SQLite，知识库用 Chroma。
- 合规：教培场景禁用承诺效果 / 保过 / 退费承诺类话术。
- 数据：只吃 MD / TXT 资料，不做 PDF 解析。

## 待验证假设

| 假设 | 内容 | 来源等级 |
|---|---|---|
| 教培行业阈值 | 24 小时首响、到访后 2 小时反馈、5–7 天二次触达、5% 僵尸线索线 | CRM 厂商文档 + 从业者自述，**未经真实机构验证** |
| 模板可迁移 | 同一套流程块能覆盖软件外包（含方案会）与建材（跳过邀约） | 设计推演，仅用于验证可迁移；**不做前端定制** |
| 员工愿意填 | 三要素留痕能被一线销售接受、不当成负担 | 未验证，靠演示反馈 |

> 前两条是 v1 的输入前提，若演示中与实际机构流程冲突，按"改模板不改引擎"处理。
